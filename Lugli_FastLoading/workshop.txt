title=Lugli - Fast Loading
description=Project Zomboid does a lot of loading work it does not need to do. This finds that work in the engine and removes it. Your loot, your items and your world are unchanged, and they are fingerprinted on every build to prove it.
description=
description=[b]300+ mods: 129s to 78s to be in the world (-40%).[/b]
description=[b]Vanilla: 20s to 13s to the main menu (-37%).[/b]

description=[h1]Needs [url=https://steamcommunity.com/sharedfiles/filedetails/?id=3619862853]ZombieBuddy[/url][/h1]
description=Almost all of this is engine patching, and ZombieBuddy is what lets a mod patch the engine. Without it only the two loot fixes run, and the mod tells you so on the main menu instead of pretending to work.
description=
description=[hr][/hr]
description=[h1]What it does[/h1]
description=[list]
description=[*]Skips the intro logos, which the game plays [i]after[/i] loading has already finished
description=[*]Walks your mod folders on 8 threads instead of one, without changing override order
description=[*]Stops the script and Lua loaders doing per file what only needs doing per folder
description=[*]Decodes textures, tilesets and shaders in parallel instead of behind one lock, and sizes the texture buffer to your machine instead of a hardcoded 50MB
description=[*]Loads vehicle textures while you sit at the menu instead of while you wait to spawn
description=[*]Builds the loot table once, after every mod has added to it, instead of once per mod
description=[*]Draws a progress bar on the loading screen the game otherwise leaves frozen
description=[/list]
description=
description=Every part can be switched off on its own, and any part that cannot enable itself says so on the main menu.
description=

description=[h1]FAQ[/h1]
description=[b]ZombieBuddy asks me to approve a Java mod.[/b]
description=That is expected. Approve it and enable the mod. ZombieBuddy never runs Java code you have not agreed to, and it only asks once.
description=
description=[b]It says "Cannot trust author: signature is invalid".[/b]
description=That message is about reaching Steam, not about the file. The jar is signed, and ZombieBuddy checks the signature by loading my Steam profile page to read the key published there, on every launch. If Steam answers with anything else (rate limit, outage, VPN, blocked connection) the check fails closed and you get that wording. Restarting the game a few minutes later usually clears it.
description=
description=If it keeps happening, tell ZombieBuddy to skip the check. Open [i]ProjectZomboid64.json[/i] in your game folder and change its ZombieBuddy entry in the [b]vmArgs[/b] list to:
description=[code]-agentlib:zbNative=policy=allow-all[/code]
description=Steam replaces that file when it updates the game, so you may need to redo it. This turns the check off for [i]every[/i] Java mod, not only this one.
description=
description=[b]Do I need it on a dedicated server?[/b]
description=Only for the loot fixes. The Java half does not load on a server at all, so the boot and texture work is client side and each player gets it from their own install. Add it to the server mod list if you want the loot fixes for everyone. Leaving it out costs nothing else.
description=
description=[b]Can I add or remove it mid-save?[/b]
description=Yes. It writes nothing into your save and nothing into your game folder.
description=
description=[b]Is it safe with my mod list?[/b]
description=It changes when work happens, not what comes out. The item database, the loot tables and the tilesets are hashed on every build and must match an unpatched run or the build fails. Where engine code is replaced, the replacement runs against the original and switches itself off if the two ever disagree.
description=
description=[b]Something looks wrong and I want to rule this mod out.[/b]
description=Add [i]-Dfastloading.logo=keep -Dfastloading.assets=off[/i] to [b]vmArgs[/b] to disable the two largest parts. The GitHub page lists all 23 switches. If that fixes it, please open an issue.
