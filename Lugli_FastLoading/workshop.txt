title=Lugli - Fast Loading
description=Removes loading work Project Zomboid does not need to do. Measured on Build 42.20.3 with a 300+ mod list, warm cache, A/B'd against the same save:
description=
description=[b]Main menu 52s to 23s (-55%)[/b] and [b]world load 123s to 57s (-54%)[/b], with loot tables byte-identical before and after.
description=
description=Scales with mod count, not map size. Every part self-enables or skips itself; no dependencies.
description=
description=[hr][/hr]
description=[h1]Boot[/h1]
description=All vanilla engine behaviour, not any one mod.
description=[table]
description=[tr][th]fix[/th][th]that phase[/th][th]running total[/th][/tr]
description=[tr][td]Intro logos skipped - they play after loading has finished[/td][td]-5.6s[/td][td][b]42.6s[/b] (-18%)[/td][/tr]
description=[tr][td]Animation meshes queued ahead of the ~8,000 textures starving them[/td][td]12.0s to 0.4s (-97%)[/td][td][b]31.2s[/b] (-40%)[/td][/tr]

description=[h1]World load[/h1]
description=[list]
description=[*][b]Loot table init[/b] - [b]7.56s to 2.16s (-71%)[/b]. The parse is vanilla, but many mods each trigger it from their own handler, so on a large list it runs ~9 times and only the last pass survives. This runs it once, after them all.
description=[*][b][url=https://steamcommunity.com/sharedfiles/filedetails/?id=3722064198]SWMG Gunworks[/url] loot insert[/b] - [b]78.3s to 8.1s (-90%)[/b], only if you run that mod. Two Lua-to-Java calls per value of every table, hoisted out of the loop.
description=[/list]

description=[h1]With [url=https://steamcommunity.com/sharedfiles/filedetails/?id=3619862853]ZombieBuddy[/url][/h1]
description=Three more parts unlock: the direct-buffer throttle serialising texture loads is removed, the asset pool is sized to your core count instead of a hardcoded four, and compiled shaders are cached. Skipped without it; everything above still applies.

description=[hr][/hr]
description=[h1]Turning parts off[/h1]
description=These are JVM properties, so they go in the [b]vmArgs[/b] list inside [i]ProjectZomboid64.json[/i] in your game folder - not Steam launch options, which never reach the JVM. Steam replaces that file on update. Almost nobody needs these.
description=[list]
description=[*][i]-Dfastloading.logo=keep[/i] play the intro logos
description=[*][i]-Dfastloading.watchergate=off[/i] keep the hot-reload watcher
description=[*][i]-Dfastloading.parse=off[/i] use the engine's tokenizer
description=[*][i]-Dfastloading.tilegeom=off[/i] parse tile geometry on the main thread
description=[/list]

description=[h1]Notes[/h1]
description=[list]
description=[*]Not tuned to one machine: buffer budget from heap size, thread pool from core count, low-core machines untouched.
description=[*]Safe to add or remove mid-save. Nothing written into your game folder.
description=[*]The early-load part registers on first launch, takes effect from the second.
description=[*]Servers get the loot fixes; asset, intro and UI parts are client-side.
description=[*]Built for [url=https://steamcommunity.com/sharedfiles/filedetails/?id=3781683109]LugliPack - B42[/url], a 300+ mod list.
description=[/list]
description=
description=[hr][/hr]
description=[h1]How this was made[/h1]
description=Every fix started by decompiling the engine to find the actual cause, then was A/B measured, quoting a band across runs rather than one lucky number. Around twenty other candidates were measured and dropped as noise, unreachable or unsafe. The kinds of work:
description=[list]
description=[*][b]More threads[/b] - the mod folder walk, the tile geometry parse, and the asset pool.
description=[*][b]Better ordering[/b] - meshes ahead of textures, so textures finish behind the menu instead of blocking it.
description=[*][b]Not repeating work[/b] - paths resolved once per folder, the loot table parsed once, calls hoisted out of inner loops.
description=[*][b]Cheaper algorithms[/b] - the tokenizer stops re-copying the rest of the file per item, and stops sharing one buffer between callers.
description=[*][b]Not doing it at all[/b] - the intro logos, and a watcher that is inert outside debug mode.
description=[/list]
description=
description=Where engine code is replaced, the replacement runs against the original and switches itself off on any disagreement, reporting it on the main menu. The item database and loot tables are fingerprinted to prove the output is unchanged.
description=
