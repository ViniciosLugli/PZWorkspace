title=Lugli - Fast Loading
description=Project Zomboid does a lot of loading work it does not need to do. This finds that work in the engine and removes it. Your loot, your items and your world are unchanged, and they are fingerprinted on every build to prove it.
description=
description=[b]300+ mods: 130s to 90s to be in the world (-31%).[/b]
description=[b]300+ mods: 47s to 32s to the main menu (-32%).[/b]
description=[b]Vanilla: 37s to 27s to be in the world (-27%).[/b]
description=
description=[img]https://raw.githubusercontent.com/ViniciosLugli/PZWorkspace/main/Lugli_FastLoading/art/proof-chart.png[/img]
description=
description=For Build 42.20 and later. Measured on 42.20.4 with 337 mods: same machine, same save, arms interleaved, every run checked against its own log. It scales with your mod count, not your map size.
description=
description=[b]Still in development, and maintained.[/b] The numbers are a snapshot, not a ceiling, and I keep it current as Build 42 moves. Where a change is faster but riskier for the base game or for other mods I take the slower option, and anything that cannot verify itself disables itself.

description=Almost all of this is engine patching and ZombieBuddy is what permits it. Without it only the two loot fixes run, and the mod says so on the main menu rather than pretending to work.

description=[hr][/hr]
description=[h1]What it does[/h1]
description=[list]
description=[*]Skips the intro logos, which the game plays [i]after[/i] loading has already finished
description=[*]Walks your mod folders on 8 threads instead of one, without changing override order
description=[*]Stops the script and Lua loaders doing per file what only needs doing per folder
description=[*]Decodes textures, tilesets and shaders in parallel instead of behind one lock, and sizes the texture buffer to your machine instead of a hardcoded 50MB
description=[*]Loads vehicle textures while you sit at the menu instead of while you wait to spawn
description=[*]Builds the loot table once, after every mod has added to it, instead of once per mod
description=[*]Indexes the [url=https://steamcommunity.com/sharedfiles/filedetails/?id=3722064198]SWMG Gunworks[/url] loot insert, 78s down to 8s, if you run that mod
description=[*]Parses tile geometry off the loading thread, and fixes a tokenizer that re-copied each script file per item
description=[*]Replaces the blank loading screen with a real one: progress bar, phase name, elapsed time and the walking figure
description=[/list]
description=
description=Every part can be switched off on its own, and any part that cannot enable itself says so on the main menu.
description=
description=[b]The loading screen looks different.[/b] That is this mod, not a bug. [code]-Dfastloading.progress=off[/code] restores the vanilla blank screen. The photosensitivity notice is hidden by default because it otherwise covers most of boot; [code]-Dfastloading.warningms=-1[/code] puts it back.
description=
description=[hr][/hr]
description=[h1]FAQ[/h1]
description=[b]ZombieBuddy asks me to approve a Java mod.[/b]
description=Expected. Approve it and enable the mod. ZombieBuddy never runs Java code you have not agreed to, and asks once.
description=
description=[b]Why is this not signed, and should I trust it?[/b]
description=ZombieBuddy verifies an unlisted author's key by fetching my Steam profile page on every launch, and anything other than that page (rate limit, outage, VPN) fails closed with no approve button. That is the "signature is invalid" people hit. Unsigned takes the ordinary approve-once path instead. My key is queued at [url=https://github.com/zed-0xff/ZombieBuddy/pull/44]PR #44[/url]; signing returns when it merges.
description=A signature would only prove the file came from this Steam account. It is not an audit. The source is what you can actually check: MIT and public, including the measurements that failed. Decompile the jar and compare it; I would rather you did. If you would rather not, do not install it. That is a reasonable decision; not subscribing or validating with real proof, then calling the author untrustworthy, is not.
description=
description=[b]Can the main menu arrive sooner?[/b]
description=There is a switch that queues animation meshes ahead of textures, and it ships off because it moves work rather than removing it: the menu arrives ~11s sooner and the world load then waits on what it deferred. Break-even is about 22 seconds on the menu and most people are quicker. If you linger there, add [code]-Dfastloading.meshprio=on[/code] to [b]vmArgs[/b].
description=
description=[b]Do I need it on a dedicated server?[/b]
description=Only for the loot fixes. The Java half never loads on a server, so the rest is client side and each player gets it from their own install.
description=
description=[b]Can I add or remove it mid-save?[/b]
description=Yes. It writes nothing into your save and nothing into your game folder.
description=
description=[b]Is it safe with my mod list?[/b]
description=It changes when work happens, not what comes out. The item database, the loot tables and the tilesets are hashed on every build and must match an unpatched run or the build fails. Replaced engine code checks itself against the original and switches off on any disagreement.
description=
description=[b]Something looks wrong and I want to rule this mod out.[/b]
description=Add [i]-Dfastloading.logo=keep -Dfastloading.assets=off[/i] to [b]vmArgs[/b] to disable the two largest parts. Every switch is listed on GitHub. If that fixes it, open an issue there.
